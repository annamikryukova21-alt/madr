# ADR-001: Выбор инфраструктуры и модели развёртывания LLM для сервиса «ЮрАссистент»

## Status

**Accepted** — 2026-11-02

**Условия пересмотра:**
- Рост нагрузки выше 1 млрд токенов/мес
- Изменение тарифов OpenAI более чем на 30%
- Ужесточение/ослабление требований 152-ФЗ
- Появление Llama 4+ с качеством уровня GPT-5 при том же железе

**Ответственный:** Архитектурный комитет

## Context

### Проблема
Для внутреннего B2B RAG-бота «ЮрАссистент» (юридическая фирма, ~200 юристов) необходимо выбрать способ хостинга LLM: проприетарная облачная модель (SaaS, GPT-5) или Open-Source модель (Llama 3 70B) на собственных GPU. Решение должно одновременно удовлетворить требованиям ИБ, уложиться в бюджет и обеспечить приемлемое качество и latency.

### Продукт
RAG-поиск по внутренней базе договоров и прецедентов, генерация черновиков ответов клиентам, суммаризация длинных документов. Автономных агентов и внешних вызовов нет — только чтение внутренней базы.

### Нагрузка
| Параметр | Значение |
|---|---|
| Запросов в день | ~3 000 |
| Пиковая нагрузка | до 15 RPS (09:00–19:00 МСК) |
| Средний промпт | ~4 000 токенов (RAG-контекст + вопрос) |
| Средний ответ | ~800 токенов |
| Токенов в месяц | ~430 млн (input + output) |
| Соотношение input : output | ~83% : 17% |

### Данные
- **Персональные данные** клиентов и сотрудников — регулируется **152-ФЗ**.
- **Коммерческая тайна**: условия сделок, цены, внутренние регламенты.
- **Адвокатская тайна** — режим повышенной конфиденциальности.
- Регулируемая отрасль: юриспруденция, требования ФПА и внутренней политики ИБ.

**Вывод:** передача ПДн и адвокатской тайны в сторонний SaaS-контур без специальных мер — **неприемлема**.

### Требования к latency
- Real-time со стримингом: **TTFT < 1,5 с**, полный ответ < 8 с.
- Batch-обработка для суммаризации — до нескольких минут на документ.
- SLO: 95% запросов в пределах указанных значений.

### Команда и инфраструктура
- 2 backend-разработчика, 1 ML-инженер, 1 DevOps (part-time).
- Есть опыт с Docker/K8s, базовый MLOps (vLLM, TGI). Выделенного специалиста по ИБ нет.
- Бюджет: до ~4 млн ₽ CAPEX + ~150 тыс. ₽/мес OPEX.
- Доступ к облаку (Yandex Cloud / Selectel) с GPU и возможность on-prem в ЦОДе партнёра.

### Регуляторные требования
- **152-ФЗ** — обработка ПДн граждан РФ, хранение и обработка на территории РФ.
- **GDPR** — не применимо, но учитывается как best practice.
- **Внутренняя политика ИБ:** запрет на передачу ПДн и адвокатской тайны третьим лицам без DPA и оценки рисков; обязательное логирование доступа.

### Рассматриваемые варианты
1. **SaaS (GPT-5 через API)** — проприетарная облачная модель.
2. **Self-hosted (Llama 3 70B на собственных GPU)** — Open-Source on-prem / в российском облаке.
3. **Гибрид** — SaaS для нечувствительных задач + self-hosted для ПДн и тайны.

### Результаты TCO-анализа (12 месяцев, курс 90 ₽/$)

| Сценарий | CAPEX | OPEX/год | **Итого/год** |
|---|---|---|---|
| SaaS (GPT-5, real-time) | ~300 000 ₽ | ~2 110 900 ₽ | **~2 410 900 ₽** |
| Self-hosted (аренда 4× L40S) | — | ~7 944 000 ₽ | **~7 944 000 ₽** |
| Self-hosted on-prem (год 1) | ~5 400 000 ₽ | ~2 872 000 ₽ | **~8 272 000 ₽** |
| **Гибрид (SaaS 70% + 2× L40S 30%)** | **~650 000 ₽** | **~4 000 630 ₽** | **~4 650 630 ₽** |

**Точка безубыточности SaaS vs self-hosted:** self-hosted окупается только при нагрузке **>1,5–2 млрд токенов/мес** (с учётом команды). При текущих 430 млн токенов/мес чистый self-hosted экономически неоправдан.

---

## Decision

**Выбираем гибридную схему:**

- **Self-hosted контур (Llama 3 70B FP8 на 2× L40S)** — для **30% трафика**, затрагивающего **ПДн, коммерческую и адвокатскую тайну, внутренние документы**. Данные не покидают периметр, соответствие 152-ФЗ обеспечивается архитектурно.
- **SaaS контур (GPT-5 через API)** — для **70% трафика** нечувствительных задач: генерация общих шаблонов, перефразирование публичных текстов, обучение сотрудников, черновики без ПДн. Используется с DPA и режимом zero-retention.
- **Маршрутизатор по чувствительности** — классификатор на входе определяет контур обработки; для спорных случаев — приоритет on-prem (fail-safe).
- **Единый слой аудита и логирования** поверх обоих контуров.

### Обоснование выбора

1. **Комплаенс.** Чистый SaaS нарушает внутреннюю политику ИБ и создаёт регуляторный риск по 152-ФЗ. Гибрид закрывает это архитектурно, а не «бумажными» мерами.
2. **Экономика.** Гибрид (~4,65 млн ₽/год) на **41% дешевле** полного self-hosted (~7,94 млн ₽/год) и лишь на **93% дороже** чистого SaaS (~2,41 млн ₽/год) — при этом снимает комплаенс-риски, которые для юрфирмы не имеют цены.
3. **Качество.** Для сложных нечувствительных задач доступен SOTA-уровень GPT-5; для чувствительных — Llama 3 70B, качество которой на типовых юридических задачах достаточно.
4. **Гибкость.** Маршрутизация позволяет перераспределять нагрузку без изменения инфраструктуры: при росте чувствительного трафика — добавить GPU, при росте общего — увеличить долю SaaS.
5. **Реалистичность для команды.** 0.5 FTE MLOps + 0.3 FTE ML — в пределах текущих компетенций; полный self-hosted потребовал бы 1–2 FTE MLOps, которых нет.


| Статья | Расчёт | Стоимость/год |
|---|---|---|
| SaaS API (70% нагрузки) | 1 260 900 × 0.7 | **882 630 ₽** |
| Аренда 2× L40S (30% нагрузки) | (4× L40S = 5 544 000) × 0.5 | **2 772 000 ₽** |
| Команда MLOps (0.5 FTE) | | **1 500 000 ₽** |
| Мониторинг и логирование | | **150 000 ₽** |
| Юридические и комплаенс-расходы | | **200 000 ₽** |
| **Итого OPEX** | | **~5 504 630 ₽** |

> **Примечание.** Аренда GPU не масштабируется пропорционально доле трафика: для Llama 3 70B нужны минимум 2× L40S (96 GB VRAM) независимо от того, 30% или 100% трафика идёт on-prem. Поэтому стоимость аренды принята как 50% от конфигурации 4× L40S (2 карты вместо 4), а не 30%. Это ключевое ограничение гибрида.

**Итого гибрид (CAPEX + OPEX): ~650 000 + 5 504 630 = ~6 154 630 ₽/год.**


## Consequences

### Positive (положительные последствия)

- ✅ **Соответствие 152-ФЗ и внутренней политике ИБ** для ПДн и адвокатской тайны — обеспечено архитектурно: данные не покидают периметр.
- ✅ **Экономия ~22%** по сравнению с полным self-hosted (~6,15 млн ₽ vs ~7,94 млн ₽/год) при сохранении комплаенса.
- ✅ **Доступ к SOTA-качеству GPT-5** для 70% нечувствительных задач — лучшее качество там, где оно важно, без компромисса по приватности.
- ✅ **Гибкость маршрутизации**: можно менять пропорции SaaS/on-prem без перестройки инфраструктуры.
- ✅ **Снижение vendor lock-in**: два независимых провайдера (OpenAI + облако GPU), отказ одного не останавливает продукт полностью.
- ✅ **Постепенное наращивание MLOps-компетенций** — команда учится на реальной задаче, а не «в вакууме».

### Negative / Trade-offs (негативные последствия, честно)

- ❌ **Усложнение архитектуры:** появляется контур классификации/маршрутизации (роутер запросов), два независимых пайплайна, единый аудит и логирование поверх них. Больше кода, больше точек отказа, сложнее отладка и тестирование.
- ❌ **Риск безопасности из-за человеческого фактора или ошибки классификатора:** если роутер пропустит ПДн в SaaS-контур — это инцидент ИБ. Требуется fail-safe (спорное → on-prem), регулярный аудит выборки и выходной PII-фильтр.
- ❌ **Аппаратные ограничения:** 2× L40S (96 GB VRAM) при пике 15 RPS для Llama 3 70B потребуют **агрессивной квантизации (INT4/AWQ)** и тонкой настройки vLLM (батчинг, paged attention), иначе возможны просадки по SLO (TTFT < 1,5 с). FP8 может не уложиться в latency при пике.
- ❌ **Фиксированная стоимость GPU:** 2× L40S нужны даже при 30% нагрузки — VRAM для 70B не масштабируется пропорционально. При снижении доли чувствительного трафика экономика гибрида ухудшается.
- ❌ **Поддержка двух стеков:** необходимо мониторить и поддерживать как внешнее API (тарифы, лимиты, деградации), так и локальный инференс (GPU, веса, квантование, инциденты). Это ~0,5 FTE MLOps постоянно.
- ❌ **SaaS-контур всё ещё требует DPA и оценки рисков** — юридическая работа не исчезает полностью, а лишь сокращается до нечувствительного трафика.
- ❌ **CAPEX ~650 000 ₽** на интеграцию и настройку инфраструктуры — невозвратные затраты при смене решения.
- ❌ **Latency on-prem контура** зависит от загрузки GPU и батчинга; при пиках возможна деградация TTFT.
